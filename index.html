Your two questions

How it's actually implemented

Both answers are demonstrated live in the prototype above — here's the engineering behind them.

01

Preventing two customers booking the same time slot

The frontend never decides availability. It only renders what the API returns. The guarantee lives at the database layer, so no race condition can slip through.

1
Customer picks a slot The API places a short soft hold on that slot for 5 minutes — visible in the demo as the countdown banner.
2
Booking submitted inside a transaction Availability is re-checked and the row inserted in one SERIALIZABLE transaction. Two simultaneous requests can't both commit.
3
Unique index is the final guard A unique constraint on (StaffId, StartTime) means the database physically rejects a duplicate — the last line of defence.
4
Loser gets a clean 409 The API returns 409 Conflict. The UI refreshes the slot list and shows a friendly message — never a crash.
// Unique index — the database's final word CREATE UNIQUE INDEX UX_Booking_Staff_Start ON Bookings (StaffId, StartTime) WHERE Status <> 'Cancelled';
02

Different permissions for the owner and staff

Permissions are enforced server-side first using ASP.NET Core Identity with roles and policies. The Angular UI only reflects what the backend already allows — so calling the API directly changes nothing.

Recommended stack

Angular + .NET — and why

You asked for a recommendation. Here it is, with the reasoning behind each layer.

Angular

Strong typing, built-in routing and reactive forms, and a component structure that stays clean as the app grows.

ASP.NET Core Web API

Clean controllers, dependency injection, policy-based authorisation and Swagger docs. Solid for booking logic.

SQL Server + EF Core

Relational integrity for bookings, customers and staff. Transactions and unique constraints handle scheduling safety.

Stripe

Optional pay-at-booking via Stripe Checkout, webhooks for payment status, and refund handling on cancellation.

Email notifications

Transactional emails for new requests, confirmations, cancellations and reminders, via a reliable provider with templates.

Identity & uploads

ASP.NET Core Identity with JWT, hashed passwords and role policies. Secure image uploads with validation and blob storage.
